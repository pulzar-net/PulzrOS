# Fleet SSH keys

Every `*.pub` here is baked into root's `authorized_keys` at image build
time, so a gateway accepts it the moment it is flashed. No bench step, no
password to read off the card, nothing typed.

It is an RSA key because the dropbear build OpenWrt ships for these targets
supported RSA alone, and gateways still on a dropbear image refuse anything
else. sshd, which replaced dropbear, takes either.

`dev/*.pub` are people's keys for a development image (`PARKEZE_DEV=1
./build.sh`), ignored by git and never read for a production one, where root
is Parkeze's alone (docs/auth.md, "Who gets root").

`ca/parkeze_user_ca.pub` is not a login key and is deliberately outside the
`*.pub` glob: it is the SSH certificate authority, trusted through
`TrustedUserCAKeys` (see docs/auth.md). In `authorized_keys` its private half
would open every gateway directly; build.sh refuses an image that puts it
there. Copy it from parkeze.net's `secrets/parkeze_ssh_ca.pub`.

`parkeze-fleet.pub` is the one that matters. Its private half belongs to
**parkeze.net**, not to a person: generated by `tools/generate-fleet-ssh-key.sh`
in that repo and mounted read-only into gateway-link. Access therefore
follows whoever operates the platform rather than whoever happened to build the
firmware, and no laptop key ships in a firmware image.

**Public keys only.** Nothing here is secret. The private half never leaves the
secret store.

## Local development

One-time setup, then it is automatic forever:

```bash
# in parkeze.net
tools/generate-fleet-ssh-key.sh secrets
cp secrets/fleet_ssh_rsa.pub ../ParkezeOS/keys/parkeze-fleet.pub
echo "FLEET_SSH_KEY_PATH=$PWD/secrets/fleet_ssh_rsa" >> .env
```

From then on every image — local or CI — accepts it:

```bash
ssh -i /path/to/secrets/fleet_ssh_rsa root@192.168.61.1
```

## Rotating

Cheap, on purpose, because an access credential should be rotatable the day
somebody leaves. Generate a new pair, rebuild, and either reflash or push the
new `authorized_keys` over the management tunnel using the old key. Unlike the fleet
*recovery* key, this does not require re-adopting anything.

## Leaving it out

A private half is root on every gateway built with its public half. That is the
same shape of risk as a shared default password — better, because a private key
is never typed, pasted into a ticket, or read aloud, but not absent.

```bash
PARKEZE_OPS_KEYS=0 ./build.sh --board rpi3
```

builds an image with no fleet key at all. Such a gateway is reachable only with
the per-unit password from its boot partition, which is what an installer
standing in front of one uses. That credential is not going away — it answers
to a different person than this one does.
